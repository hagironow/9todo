# Spec: todoslot MVP

> 작성일: 2026-05-05
> 작성: planner
> 상태: 검토 중
> 범위: MVP (Phase 1)
> 페르소나: 지호 (1차 타겟 — 바이브 코더), 수민 (2차 타겟 — 사이드 프로젝트 메이커)

---

## 1. 한 줄 요약

9칸 시간표(아침/저녁/밤 × 1·2·3순위)로 오늘의 시간 배분을 강제하고, Now Focus로 지금 해야 할 것 하나를 3초 안에 보여주는 웹앱.

---

## 2. 배경

### 페르소나의 좌절

- **지호**: "아침에 '오늘 뭐 하지?'로 시작해서 30분 낭비. 할 일이 20개인데 실제로 끝내는 건 2개." (personas.md)
- **수민**: "퇴근 후 '뭐부터 하지?' 고민하다 넷플릭스 시청. 사이드 프로젝트별로 뭘 해야 하는지 한눈에 안 보임." (personas.md)

### 매칭 시나리오

scenarios.md의 **1단계 핵심 시나리오 전체**:
- 시나리오 A: 아침에 오늘의 시간표 세팅하기
- 시나리오 B: Now Focus로 집중하고 완료하기
- 시나리오 C: 미루기 — 다음 시간대로 밀기
- 시나리오 D: 루틴 등록과 자동 재생성
- 시나리오 E: 백로그에서 스케줄링
- 시나리오 F: 프로젝트별 필터링

### Vision / Positioning 근거

- "오늘 하루, 지금 이 시간에 뭘 해야 하는지 3초 안에 알 수 있어야 한다." (vision.md 북극성)
- "9칸 강제 제한: 우선순위를 강제하는 구조." (positioning.md)
- MVP는 로컬 JSON 기반 웹앱 (vision.md)

## 3. 데이터 모델

### 3-1. TypeScript 타입 정의

```typescript
// ── 기본 단위 ──────────────────────────────────────────

/** 시간대 (core-concepts.md 정의 준수) */
type TimePeriod = 'morning' | 'afternoon' | 'evening';

/** 우선순위 (core-concepts.md 정의 준수) */
type Priority = 1 | 2 | 3;

/** 슬롯 좌표 (core-concepts.md 코드 규칙 준수) */
interface SlotCoord {
  period: TimePeriod;
  priority: Priority;
}

/** 루틴 반복 주기 */
type RecurrenceType = 'daily' | 'weekly' | 'biweekly' | 'monthly';

// ── 프로젝트 ───────────────────────────────────────────

interface Project {
  id: string;           // nanoid (예: "proj_abc123")
  name: string;         // 프로젝트 이름
  color: string;        // CSS 색상값 (예: "#4ADE80")
  createdAt: string;    // ISO 8601
}

// ── 항목 (Item = Task | Routine) ──────────────────────

/** 공통 필드 */
interface ItemBase {
  id: string;             // nanoid (예: "item_abc123")
  title: string;          // 할 일 제목
  projectId: string | null; // 연결된 프로젝트 (없으면 null)
  createdAt: string;        // ISO 8601
}

/** 태스크 (일회성) */
interface Task extends ItemBase {
  type: 'task';
  slot: SlotCoord | null;    // null = 백로그 상태
  deferCount: number;        // 미룬 횟수 (기본값 0)
  completedAt: string | null; // 완료 시각 (null = 미완료)
  date: string;              // 소속 날짜 "YYYY-MM-DD"
}

/** 루틴 (반복) */
interface Routine extends ItemBase {
  type: 'routine';
  recurrence: RecurrenceType;
  defaultSlot: SlotCoord;      // 루틴의 기본 배치 슬롯
  startDate: string;           // 루틴 시작 날짜 "YYYY-MM-DD"
  isActive: boolean;           // 루틴 활성 여부
}

/** 루틴 인스턴스: 특정 날짜에 생성된 루틴의 실행 기록 */
interface RoutineInstance {
  id: string;                  // nanoid
  routineId: string;           // 원본 Routine.id
  date: string;                // 소속 날짜 "YYYY-MM-DD"
  slot: SlotCoord;             // 이 날 실제 배치된 슬롯 (미루기로 변경 가능)
  deferCount: number;
  completedAt: string | null;
}

/** 화면에서 사용하는 통합 타입 */
type ScheduledItem = (Task | RoutineInstance) & { routineDetails?: Routine };

// ── 앱 상태 ───────────────────────────────────────────

interface AppState {
  projects: Project[];
  tasks: Task[];
  routines: Routine[];
  routineInstances: RoutineInstance[];
  /** 마지막으로 사용한 프로젝트 ID (빠른 추가 자동 연결용) */
  lastUsedProjectId: string | null;
  /** 현재 활성 프로젝트 필터 (null = 전체 보기) */
  activeProjectFilter: string | null;
}
```

### 3-3. 데이터 접근 패턴 (Phase 1 로컬 JSON)

- **읽기**: 앱 초기화 시 `data/todoslot.json` 파일 전체 로드 → 메모리(React state)에서 관리
- **쓰기**: 상태 변경마다 전체 JSON을 덮어쓰기 (debounce 300ms)
- **API 라우트**:
  - `GET /api/data` — JSON 전체 반환
  - `PUT /api/data` — JSON 전체 교체 저장
- **날짜 롤오버**: 앱 최초 로드 시 오늘 날짜 확인 → 어제 날짜의 미완료 태스크는 백로그로 이동 (slot = null, date 유지)
- **루틴 인스턴스 생성**: 앱 최초 로드 시 오늘 날짜의 루틴 인스턴스가 없으면 자동 생성

## 4. UX 흐름

### 4-1. 빠른 추가 (시나리오 A, E)

```
1. 상단 QuickInput 포커스
2. 제목 입력
3. Enter / "추가" 버튼 클릭
4. 마지막 사용 프로젝트가 자동 연결됨
   └─ 프로젝트가 없으면 연결 없음(null)
5. 백로그에 즉시 추가
6. 인풋 초기화 + 포커스 유지
```

선택적 플로우:
```
3-a. "@프로젝트명" 접두사 입력 시 해당 프로젝트 자동 연결
3-b. 루틴으로 만들고 싶으면 "반복" 체크 후 주기 선택 → 루틴 생성
```

### 4-2. 스케줄링 (시나리오 E)

**방법 A: 백로그 항목 → 슬롯 선택**
```
1. 백로그 패널에서 항목 클릭
2. SlotPickerModal 표시: 3x3 격자
   └─ 이미 채워진 슬롯은 비활성화 (흐리게)
3. 빈 슬롯 클릭 → 해당 슬롯에 배치
4. 모달 닫힘 → 시간표에 항목 표시
```

**방법 B: 빈 슬롯 → 백로그에서 선택**
```
1. 시간표의 빈 슬롯(+ 버튼) 클릭
2. BacklogPickerModal 표시: 백로그 항목 목록
   └─ 프로젝트별 그룹핑
3. 항목 클릭 → 해당 슬롯에 배치
4. 모달 닫힘 → 시간표에 항목 표시
```

### 4-3. Now Focus 자동 선택

```
현재 시각 기준으로 현재 시간대 결정
  └─ 06:00~12:00 → morning
  └─ 12:00~18:00 → afternoon
  └─ 18:00~24:00 → evening
  └─ 00:00~06:00 → evening (전날 밤 연장)

현재 시간대의 priority=1 슬롯 항목 → Now Focus에 표시
  └─ 해당 슬롯이 비어 있으면 → priority=2, 3 순서로 폴백
  └─ 시간대 전체가 비어 있으면 → "지금 시간표가 비어 있어요" 상태
```

### 4-4. 완료 (시나리오 B)

```
1. 항목 카드의 체크버튼 클릭
2. 취소선 + fade-out 애니메이션 (0.5초)
3. completedAt = 현재 시각 기록
4. 시간표에서 사라짐
5. Now Focus 자동 갱신: 2순위 항목이 1순위 자리로 올라옴
```

루틴 인스턴스 완료:
```
3-a. 루틴 인스턴스의 completedAt = 현재 시각
3-b. 다음 발생일에 새 인스턴스 자동 생성 예약 (날짜 롤오버 시 처리)
```

### 4-5. 미루기 (시나리오 C)

```
1. 항목 카드의 미루기 버튼(→) 클릭
2. 다음 시간대 계산:
   └─ morning → afternoon
   └─ afternoon → evening
   └─ evening → 내일 morning (날짜 +1, date 변경)
3. slot 업데이트:
   └─ 다음 시간대의 priority=1 슬롯이 비어 있으면 → 그 자리로
   └─ 비어 있지 않으면 → priority=2, 3 순서로 폴백
   └─ 모두 차 있으면 → 백로그로 이동 (slot = null)
4. deferCount += 1
5. Now Focus 자동 갱신
```

### 4-6. 루틴 등록 (시나리오 D)

```
1. QuickInput에서 "반복" 토글 활성화
2. 제목 입력 + Enter
3. RoutineSetupModal 표시:
   └─ 반복 주기 선택 (매일 / 매주 / 격주 / 매월)
   └─ 기본 배치 슬롯 선택 (3x3 격자)
   └─ 시작 날짜 (기본값: 오늘)
4. "등록" 클릭 → Routine 객체 생성
5. 오늘 날짜에 RoutineInstance 즉시 생성 → 지정 슬롯에 배치
```

### 4-7. 프로젝트 필터링 (시나리오 F)

```
1. 사이드바의 컬러 도트 클릭
2. activeProjectFilter = 해당 projectId
3. 시간표: 해당 프로젝트 항목만 표시 (다른 슬롯은 빈 상태로 표시)
4. 백로그: 해당 프로젝트 항목만 표시
5. 같은 도트 다시 클릭 → 필터 해제 (전체 보기)
```

### 5-2. Now Focus 섹션

- 배경: `var(--accent)` 코랄 (#FF5C65), 텍스트: `var(--accent-foreground)` 흰색
- 현재 시간대 레이블 (예: "저녁 1순위") — `var(--fs-tag)` 14px, 반투명
- 항목 제목 — 24px bold, 1줄 ellipsis
- 컬러 도트 — 프로젝트 색상 원 (직경 8px)
- 버튼: [체크 완료] [→ 미루기]
- 항목이 없을 때: "지금 시간표가 비어 있어요. 슬롯에 할 일을 추가해 보세요." 상태 텍스트

### 5-3. 시간표 그리드

- 현재 시간대 행: 배경 `var(--card)` + 왼쪽 4px 보더 `var(--accent)`로 강조
- 지나간 시간대: opacity 0.5로 dimmed
- 오지 않은 시간대: 기본 스타일

**슬롯 카드 (채워진 상태)**
- 배경: `var(--card)`
- 제목: `var(--fs-item)` 15px
- 컬러 도트: 프로젝트 색상 (좌측)
- deferCount > 0: 주황색 숫자 뱃지 (예: ②)
- 루틴 인스턴스: 점선 테두리 + ↻ 아이콘 + `var(--muted)` 배경
- 호버 시: 체크 버튼 + 미루기 버튼 오버레이 표시

**슬롯 (빈 상태)**
- 배경: 투명 + `var(--border)` 점선 테두리
- 중앙: + 아이콘 (클릭 시 BacklogPickerModal)

### 5-4. QuickInput

- 화면 상단 고정 (데스크톱: 메인 영역 상단, 모바일: 헤더 아래)
- 텍스트 인풋 + [추가] 버튼
- 인풋 좌측: 프로젝트 컬러 도트 (마지막 사용 프로젝트)
  - 클릭 시 ProjectPicker 드롭다운
- 인풋 우측: [반복] 토글 (체크 시 루틴 모드)
- placeholder: "할 일 추가... (@프로젝트명으로 연결)"

### 5-5. 백로그 패널

- 기본 상태: 접힘 (▸ 백로그 3개 항목)
- 클릭 시: 펼침 (▾ 백로그)
- 내용: 프로젝트별 그룹 헤더 + 항목 목록
  - 그룹 헤더: 컬러 도트 + 프로젝트명 + 항목 수
  - 항목 행: 제목 + deferCount 뱃지 + [슬롯 배치] 버튼
  - 프로젝트 없는 항목: "미분류" 그룹
- 빈 상태: "백로그가 비어 있어요."

### 5-6. 사이드바

- 앱 로고/이름 (최상단)
- 프로젝트 목록:
  - 컬러 도트 + 프로젝트명
  - 클릭 시 필터 활성화 (활성 상태: 배경 강조)
  - 전체 보기 버튼 (필터 해제)
- [+ 새 프로젝트] 버튼 → ProjectCreateModal

### 5-7. 모달: SlotPickerModal

- 3x3 격자 표시
- 행 레이블: 아침 / 저녁 / 밤
- 열 레이블: 1순위 / 2순위 / 3순위
- 빈 슬롯: 클릭 가능, 흰 배경
- 채워진 슬롯: 흐리게 + 항목 제목 미리보기, 클릭 불가
- 선택 시 즉시 배치 + 모달 닫힘

### 5-8. 모달: RoutineSetupModal

- 반복 주기 선택: 버튼 그룹 (매일 / 매주 / 격주 / 매월)
- 기본 배치 슬롯: SlotPickerModal과 동일한 3x3 격자
- 시작 날짜: Date input (기본값: 오늘)
- [등록] / [취소] 버튼

## 7. 인터랙션 상세

### 7-1. 현재 시간대 하이라이트

- `useCurrentPeriod` 훅: `setInterval` 60초마다 현재 시각 확인 → 시간대 재계산
- 현재 시간대 행: `border-l-4 border-accent` + 배경 `bg-card`
- 지나간 시간대: `opacity-50` (완료 항목이 없으면 주황 처리는 Phase 2)

### 7-2. 완료 애니메이션

- 체크 클릭 시:
  1. 항목 카드에 `line-through` + `opacity-50` 즉시 적용
  2. `animate-fade-out` (tokens.css 정의, 2초)
  3. 2초 후 completedAt 기록 + 상태 업데이트 → 카드 DOM에서 제거

### 7-3. 미루기 횟수 시각화

- `deferCount === 0`: 뱃지 없음
- `deferCount === 1`: 회색 뱃지 "1"
- `deferCount === 2`: 주황 뱃지 "2"
- `deferCount >= 3`: 빨간 뱃지 "3" + 카드 테두리 주황색 + 툴팁 "3번 미뤘어요"

### 7-4. 슬롯 9개 초과 방지

- 슬롯이 꽉 찬 상태에서 스케줄링 시도 시:
  - SlotPickerModal: 모든 슬롯 비활성화, 상단 안내 "오늘 슬롯이 꽉 찼어요. 기존 항목을 완료하거나 미루세요."
  - 빠른 추가 후 백로그에는 추가됨 (슬롯 배치만 제한)

### 7-5. 프로젝트 자동 연결 (빠른 추가)

- `lastUsedProjectId`가 있으면 인풋 좌측 도트에 해당 프로젝트 색상 표시
- "@프로젝트명" 파싱: 입력값에서 `@`로 시작하는 첫 번째 토큰을 프로젝트명으로 매칭
  - 매칭 성공: 해당 projectId 연결 + "@프로젝트명" 제거 → 제목만 남김
  - 매칭 실패: 토큰 그대로 유지 (제목의 일부로 처리)

## 10. 검증 방법

시나리오 기반으로 아래 흐름이 모두 동작하면 MVP 완료:

1. **시나리오 A**: 앱 열었을 때 어제 미완료 항목이 백로그에 보임. QuickInput으로 항목 추가 후 SlotPickerModal에서 슬롯 배치 가능. Now Focus에 아침 1순위 표시.
2. **시나리오 B**: 현재 시간대에 맞는 1순위 항목이 Now Focus에 표시됨. 체크 버튼 클릭 시 취소선 + fade-out 후 제거. Now Focus 자동 갱신.
3. **시나리오 C**: 미루기 버튼 클릭 시 다음 시간대로 이동. deferCount 숫자 뱃지 증가. 밤에서 미루면 내일 아침으로.
4. **시나리오 D**: 루틴 토글 후 항목 추가 → RoutineSetupModal에서 매일 반복 + 저녁 2순위 설정. 다음 날 앱 열면 해당 슬롯에 루틴 인스턴스 자동 배치.
5. **시나리오 E**: 백로그 패널 펼침. 항목 클릭 → SlotPickerModal에서 슬롯 선택 → 시간표에 배치됨.
6. **시나리오 F**: 사이드바 컬러 도트 클릭 → 해당 프로젝트 항목만 필터링. 다시 클릭 → 전체 보기 복귀.

## 11. 미해결 / 결정 필요

1. **목표 대시보드 (Goal Compass)**: 컨셉 문서에 상세 정의됐으나 MVP 시나리오에 없어 Phase 2로 보류. 지호/수민 페르소나가 이 기능을 원하는지 별도 검증 필요.

2. **시간대 커스텀**: core-concepts.md에 "사용자가 커스텀 가능"으로 명시됐으나 MVP 구현에서 제외. "기본값 06/12/18/24 고정"으로 시작. 사용자 불만 시 Phase 2 추가.

3. **미루기 대상 슬롯 우선순위**: 다음 시간대로 이동 시 해당 시간대가 꽉 찬 경우 백로그로 떨어뜨리는 것이 올바른가? 또는 "이동 불가" 알림으로 처리할 것인가. 현재 사양은 백로그 이동으로 결정됨.

4. **루틴 인스턴스 기본 슬롯 충돌**: 루틴의 defaultSlot에 이미 다른 항목이 있을 때 어느 슬롯으로 생성할 것인가. 현재 사양은 충돌 시 백로그로 생성(slot = null, 사용자가 수동 배치)으로 결정됨.

5. **완료 항목 영구 보존 vs 삭제**: completedAt을 기록하되 todoslot.json에 남겨두는가, 일정 기간 후 삭제하는가. Phase 1에서는 영구 보존(정리 없음). JSON 파일 비대화 가능성 있음.

6. **다크 모드 토글 UI**: tokens.css에 `.dark` 클래스 정의됨. 토글 버튼을 사이드바에 넣을 것인가, 별도 설정 페이지로 뺄 것인가. MVP에서는 OS 기본값 따름(`prefers-color-scheme`).
