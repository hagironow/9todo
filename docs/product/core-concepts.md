# Core Concepts

> 이 문서는 프로젝트의 도메인 용어를 정의한다.
> 코드, 문서, UI에서 동일한 용어를 사용한다.

## 슬롯 (Slot)
3x3 시간표 격자의 한 칸. 시간대(행)와 우선순위(열)의 교차점.
하루 최대 9개의 슬롯이 존재하며, 각 슬롯에는 하나의 태스크 또는 루틴이 배치된다.
**슬롯이 9block의 핵심 단위이자 정체성이다.** 할 일을 "쓰는" 것이 아니라 슬롯에 "끼워넣는" 행위가 UX의 중심.

## 시간대 (Time Period)
하루를 3개로 나눈 시간 구간. 시간표의 행에 해당한다.
- **아침 (Morning)**: 기본 06:00~12:00. 집중 작업(제작) 시간.
- **저녁 (Afternoon)**: 기본 12:00~18:00. 혼합(제작+배포) 시간.
- **밤 (Evening)**: 기본 18:00~24:00. 가벼운 작업(배포, 리뷰) 시간.

시간 범위는 사용자가 커스텀 가능하다.

## 우선순위 (Priority)
슬롯의 열에 해당. 1순위, 2순위, 3순위의 3단계.
같은 시간대 내에서 어떤 것을 먼저 해야 하는지를 결정한다.
1순위는 Now Focus에 표시되는 항목이다.

## 태스크 (Task)
반복 없는 일회성 할 일. 자연스럽게 "제작" 성격을 갖는다.
예: "플로디 사이드바 리팩터링", "랜딩 페이지 작성"

## 루틴 (Routine)
반복 스케줄이 있는 항목. 자연스럽게 "배포" 성격을 갖는다.
주기: 매일 / 매주 / 격주 / 매월.
완료 시 다음 발생일에 자동 재생성된다.
시각적으로 점선 테두리 + 반복 아이콘 + 회색 배경으로 구분된다.

## 플레이 섹션 (Play Section)
화면 상단에 표시되는 "지금 할 것". 현재 시간대의 슬롯 아이템을 플레이 버튼과 함께 표시한다.
1순위가 메인(큰 카드), 2~3순위는 하단에 작은 카드로 병렬 표시된다.
프로젝트 컬러가 배경색으로 적용되어 어떤 프로젝트의 작업인지 즉시 파악 가능.
활성 시간대에서만 병렬 플레이가 가능하며, 최대 3개의 플레이 섹션이 동시에 표시된다.

## 미루기 (Defer)
현재 슬롯의 항목을 **백로그로 보내는** 행위.
슬롯이 비워지고, 해당 항목은 백로그에서 대기한다. 나중에 다시 슬롯에 배정할 수 있다.
미룬 횟수가 누적 표시되어 자각을 유도한다 (예: 숫자 뱃지 3).
"3번 미뤘네, 진짜 할 건가?" -- 미루기의 비용을 시각화.

## 또하기 (Replay)
현재 항목을 **복사하여 새로운 슬롯에 재배정**할 수 있게 하는 행위.
원본은 그대로 두고, 복사본이 백로그에 생성되어 드래그 앤 드랍으로 원하는 슬롯에 배치.
용도: (1) 못 끝낸 작업을 다른 시간대에 이어서, (2) 비슷한 작업을 반복 수행.
(임시 워딩 -- 더 나은 이름 추후 검토)

## 백로그 (Backlog)
시간표에 배치되지 않은 모든 항목의 대기열.
화면 하단에 접힌 상태로 표시되며, 프로젝트별로 그룹핑된다.
여기서 항목을 골라 드래그 앤 드랍으로 슬롯에 배치(스케줄링)한다.
미루기된 항목도 이곳으로 돌아온다.

## Goal Compass
시간표 위에 위치하는 방향 확인 섹션.
접힌 상태에서 **"오늘 끝낼 일은 [오늘 목표]"** 형태로 미리보기를 표시한다.
펼치면 "나는" 정체성 인풋과 목표 계층(오늘/이번주/이번달/분기/1년/5년)이 나타난다.
확언(Affirmation)은 별도 섹션으로 분리되어 Goal Compass 바로 아래에 위치한다.

## 확언 (Affirmation)
Goal Compass 아래에 위치하는 별도 섹션. 사용자가 **직접 작성**한 한 문장.
프리셋이나 랜덤 로테이션 없이, 사용자 본인의 말로 쓴 것만 의미 있다.
예: "출시하지 않으면 아무것도 아니다", "매일 1% 더 나아지자"

## 프로젝트 (Project)
관련 태스크/루틴을 묶는 최상위 단위. 생성 시 필요한 것은 **이름 + 색 하나**뿐.
할 일 카드에 컬러 도트로 표시되며, 사이드바에서 프로젝트별 필터링이 가능하다.

## 태그 (Tag)
프로젝트 하위의 유연한 분류 단위. 사람마다 다른 분류 방식을 수용한다.
예: "업무" 프로젝트 하위에 "기획", "개발", "배포" 태그. 또는 "플로디" 프로젝트에 "v2", "버그" 태그.
태그끼리 모아보기(필터링)가 가능하다.
프로젝트가 "어떤 프로젝트인가?"라면, 태그는 "어떤 종류의 작업인가?"를 나타낸다.

## 컬러 도트 (Color Dot)
프로젝트를 나타내는 작은 색상 원. 할 일 카드의 프로젝트 표시 방법.
복잡한 프로젝트 관리 UI 대신 색 하나로 시각적 구분을 제공한다.

## 로미 (Romi) — 우선순위 도우미
타임박싱 프로세스를 가이드하는 온보딩 캐릭터 (가칭).
매일 첫 접속 시 등장하여 사용자가 오늘의 작업을 설정하도록 돕는다.

**온보딩 플로우:**
1. "안녕하세요! 저는 우선순위 도우미 로미에요. 오늘은 어떤 일을 완료해볼까요?"
2. 오늘 끝낼 일 하나를 정하게 한다
3. 그 하위 태스크를 분리해서 쓰게 한다
4. 쪼갠 태스크를 슬롯에 배치시킨다

**핵심 가치:** 사람들이 태스크를 어떻게 쪼갤지, 우선순위를 어떻게 배치할지 모르기 때문에 이 과정을 대신 안내한다.
9칸 슬롯이라는 제약 안에서 "이 일을 마무리하려면 어떻게 쪼개는 게 좋을지" 자연스럽게 학습하게 된다.

**위치:** 브라우저 우측 하단 플로팅 아이콘. 첫 접속 시 자동 등장, 이후 아이콘 클릭으로 재호출.

**확장 (Phase 2+):** AI 연동으로 태스크 분해를 자동 제안.

## 스케줄링 (Scheduling)
백로그의 항목을 시간표 슬롯에 배치하는 행위.
기본 인터랙션은 **드래그 앤 드랍**. 백로그에서 항목을 잡아 원하는 슬롯에 놓는다.
대안: 빈 슬롯 클릭 후 백로그에서 선택. 또는 로미 가이드를 통한 단계별 배치.

## 소셜/경쟁 시스템 (Phase 2+)
나의 완료율을 다른 사람들에게 공개하는 상호 감시 시스템.
- **완료율 공개**: 오늘 9칸 중 몇 개를 깼는지 실시간 표시
- **팔로우**: 다른 사용자의 완료율을 구독
- **배틀 시스템**: 1:1 또는 그룹 단위로 완료율 대결
- 서비스명 후보: "투두리그(TodoLeague)" — 리그/랭킹 시스템과의 연결

## 용어 규칙
- "할 일"의 상위 개념으로 "항목(Item)"을 사용한다. 태스크와 루틴을 모두 포함.
- "카테고리", "레이블"은 사용하지 않는다. 9block에는 프로젝트(컬러 도트)와 태그가 있다.
- "시간 블록"은 사용하지 않는다. 9block의 단위는 "시간대"(아침/저녁/밤)다.
- "제작"과 "배포"는 UI에 노출하지 않는다. 태스크/루틴이라는 구조가 이를 대신한다.
- "타임라인"은 사용하지 않는다. 9block은 "시간표"(격자)다.
- 코드에서 슬롯 좌표는 `{ period: 'morning' | 'afternoon' | 'evening', priority: 1 | 2 | 3 }` 형태를 사용한다.
