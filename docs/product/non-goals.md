# Non-Goals (1단계)

> **이 목록은 게이트키퍼 역할.**
> PO 에이전트는 새 기능 요청이 들어오면 이 목록과 충돌하는지 먼저 확인한다.

## 안 한다

| 항목 | 이유 | 언제 재고? |
|---|---|---|
| 팀 협업 / 공유 기능 | 개인의 시간 배분 도구. 멀티유저는 복잡성을 폭발시킨다. | 1.0 이후 수요 검증 시 |
| 소셜/경쟁 시스템 (투두리그) | 완료율 공개, 팔로우, 배틀. 핵심 루프가 검증된 후 도입. | Phase 2 |
| 분 단위 시간 블록 | 아침/저녁/밤 3칸이 핵심 메타포. 세분화하면 캘린더와 다를 바 없다. | 재고하지 않음 |
| 태그 / 레이블 / 카테고리 시스템 | 프로젝트가 유연한 분류 역할을 대신한다. 수동 태그 대신, AI 기반 자동 분류로 통계를 제공할 예정 (유료 기능). | Phase 2 (AI 자동 분류) |
| 서버 동기화 / 클라우드 저장 | Phase 1은 로컬 JSON. 데이터 구조가 안정된 후 동기화 고려. | Phase 2 |
| 10개 이상의 슬롯 | 9칸 강제 제한이 핵심 가치. 늘리면 "또 다른 무한 투두앱"이 된다. | 재고하지 않음 |
| 알림 / 리마인더 | MVP에서는 앱을 열었을 때 Now Focus로 충분. 알림은 피로를 유발. | Phase 2 |
| 통계 / 리포트 / 대시보드 | MVP의 핵심은 "오늘"에 집중하는 것. 과거 분석은 우선순위 밖. 단, 날짜 네비게이션(캘린더 모달 → 해당 날짜 데이터 리드)은 기본 기능으로 Phase 1에 포함. 별도 뷰가 아니라 동일 뷰에서 날짜만 전환. | Phase 2 (통계/분석은 유지, 날짜 이동은 Phase 1) |
| macOS 위젯 | Swift WidgetKit 필요. 웹앱 MVP가 검증된 후 Phase 3에서 진행. | Phase 3 |
| 네이티브 데스크톱 앱 (Tauri) | 웹앱으로 충분한지 검증 후 결정. | Phase 2 |
| 타임라인 시각화 | 9todo은 시간표(격자)지 타임라인(줄)이 아니다. 슬롯 메타포를 지킨다. | 재고하지 않음 |
| 명언 프리셋 / 랜덤 로테이션 | Goal Compass의 확언은 사용자가 직접 쓰는 것. 프리셋/랜덤은 의미 희석. | 재고하지 않음 |
| 태스크 내 노트/설명 필드 | 50자 한 줄이 전부. "열어봐야 하는 태스크"는 3초 원칙을 깬다. ADHD 사용자에게 빈 노트 필드는 함정. | 재고하지 않음 |
| 서브태스크 | 큰 일은 쪼개서 각각 슬롯에 넣는 것이 9todo의 방식. 슬롯 안에 트리 구조를 만들지 않는다. | 재고하지 않음 |
| 첨부파일/링크 필드 | 9todo는 참고자료 보관소가 아님. 태스크명 50자 안에 키워드를 넣을 것. | 재고하지 않음 |

## 게이트키퍼 규칙

새 기능 요청이 위 목록과 겹치면:
1. PO 에이전트가 사용자에게 푸시백
2. 그래도 진행하려면 -> 해당 항목을 이 문서에서 제거하고 재고 사유 기록
3. 회피(workaround)가 가능한지 먼저 탐색
